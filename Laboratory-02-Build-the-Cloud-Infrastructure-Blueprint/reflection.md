# Mission Reflection

This laboratory activity gave me an opportunity to work with cloud infrastructure in a more practical way. Through the KillerCoda Playground, I was able to access a Linux environment and investigate the resources of a server. This made it easier for me to connect the concepts from the lesson with an actual working system.

Among the infrastructure components, I consider **compute resources** to be one of the most important because they allow the server to process information and perform tasks. The CPU, CPU core, and RAM determine the computing resources available to the system and its applications.

I also gained a better understanding of how Linux supports cloud computing. The terminal allows users to inspect different parts of a server through commands. I used commands such as `cat /etc/os-release`, `uname -r`, `nproc`, `free -h`, `df -h`, `findmnt`, `hostname`, and `hostname -I`. At first, some of these commands were new to me, but using them helped me understand their functions.

Technical documentation was another important lesson from this activity. Keeping infrastructure information organized makes it easier to review and understand the configuration of a system. It can also help when checking resources or troubleshooting possible problems.

I developed several useful skills during the laboratory, including Linux command-line usage, system information gathering, Markdown formatting, cloud provider comparison, and GitHub documentation. I also learned how different infrastructure resources contribute to a complete cloud environment.

After completing the activity, my GitHub portfolio became more organized because I added my investigation results, cloud provider comparison, infrastructure documentation, diagram, and reflection. Overall, this laboratory improved my confidence in using Linux and gave me a better foundation for studying cloud computing.
